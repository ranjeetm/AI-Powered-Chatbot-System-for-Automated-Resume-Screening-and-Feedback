# Recommended Next Step Order

## Phase 1 — Backend Production Hardening (Highest Priority)

This should be your immediate next step.

---

## 1. Centralize Configuration Management

### Goal

Move all secrets/configs into environment variables.

### Create

```bash
backend/.env
frontend/.env.local
```

### Backend Variables

```env
DATABASE_URL=
OPENROUTER_API_KEY=
EMBEDDING_MODEL=
SECRET_KEY=
CORS_ORIGINS=
```

### Frontend Variables

```env
NEXT_PUBLIC_API_URL=
```

### Install

```bash
pip install python-dotenv
```

### Create

```bash
backend/core/config.py
```

### Why This Matters

* Production-safe
* Easier deployment
* Cleaner architecture
* Environment separation

---

## 2. Add Alembic Database Migrations

### Goal

Manage PostgreSQL schema professionally.

### Install

```bash
pip install alembic
```

### Initialize

```bash
alembic init alembic
```

### Configure

* Link SQLAlchemy models
* Connect DATABASE_URL
* Create migration scripts

### Benefits

* Version-controlled DB schema
* Safe production updates
* Easier collaboration

---

## 3. Refactor Into Layered Backend Architecture

Your backend is growing.
Now separate logic properly.

## Recommended Structure

```text
backend/
│
├── api/
├── core/
├── db/
├── models/
├── schemas/
├── services/
├── repositories/
├── utils/
├── ranking/
├── embeddings/
├── llm/
└── ingestion/
```

### Key Separation

| Layer        | Responsibility      |
| ------------ | ------------------- |
| API          | Routes only         |
| Services     | Business logic      |
| Repositories | DB queries          |
| Schemas      | Pydantic validation |
| Models       | SQLAlchemy tables   |
| Utils        | Shared helpers      |
